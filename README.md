# Element Quest

A self-paced periodic table learning app for students. They explore all 118 elements, review with spaced repetition, take quizzes and watch their mastery map fill in. A parent or teacher sees their progress. It runs in Docker on a Mac and is reachable from any phone, tablet or laptop on the home Wi-Fi.

| Part | Tech | Port |
| --- | --- | --- |
| `web` | React 19 + TypeScript (Vite), Tailwind CSS, served by Nginx | 8080 on your Mac, open to your Wi-Fi |
| `api` | Python FastAPI, SQLAlchemy, Alembic | internal only |
| `db` | PostgreSQL 17 | internal only |

## Run it on your Mac

1. Install [Docker Desktop for Mac](https://docs.docker.com/desktop/setup/install/mac-install/) and start it.
2. Get the code and create your settings file (`.env`, with random passwords):

   ```sh
   git clone https://github.com/itsmtoolexpert/element-quest.git
   cd element-quest
   ./scripts/setup.sh
   ```

   It prints the Parent / Teacher password. Keep it. To pick your own, edit `ADMIN_PASSWORD` in `.env` before step 3.
3. Start it (always from inside the `element-quest` folder, where `.env` lives):

   ```sh
   docker compose up -d --build
   ```

4. Open <http://localhost:8080>.

The first start creates the database, loads all 118 elements and creates three accounts:

| Account | Who | Password |
| --- | --- | --- |
| Soy Sauce | student | `STUDENT_DEFAULT_PASSWORD` (default `elements`) |
| Ketchup King | student | same |
| Parent / Teacher | admin | `ADMIN_PASSWORD` |

Stop with `docker compose down`. Data stays in the `db-data` volume; only `docker compose down -v` deletes it.

## Open it from phones and tablets

1. Find your Mac's local name: System Settings → General → Sharing, under "Local hostname" (for example `rahuls-macbook.local`).
2. On a phone on the same Wi-Fi, open `http://rahuls-macbook.local:8080`.
3. The first time, macOS may ask whether Docker can accept incoming connections. Click **Allow**.
4. If the `.local` name doesn't work on an Android device, use the Mac's IP address instead (System Settings → Wi-Fi → Details). Give the Mac a fixed IP in your router so it never changes.

The Mac has to be awake. To keep it awake while plugged in: System Settings → Battery → Options → "Prevent automatic sleeping when the display is off".

The app is plain HTTP and only reachable on your home network. Don't forward port 8080 on your router.

## Put it on the home screen

**iPhone / iPad (Safari):** open the address, tap Share → **Add to Home Screen**. It opens full screen with its own icon.
**Android (Chrome):** open the address, tap ⋮ → **Add to Home screen**.

Over plain `http://` this is a shortcut to the live app, so it needs the Mac awake. If the Mac sleeps while a student is using the app, a "Can't reach Element Quest" banner appears and the app reconnects by itself when the Mac wakes. If the Mac is already asleep when they open it, the browser shows its own error page, because nothing is answering. HTTPS (below) fixes that case.

### Optional: HTTPS for a full app install

Browsers only allow the full app install over HTTPS (or on `localhost`). With it, the app still opens while the Mac is asleep: Explore keeps working from a saved copy of the elements and materials, and practice waits for the Mac to wake. To turn it on:

```sh
brew install mkcert
./scripts/https-setup.sh
```

The script makes a certificate for your Mac, switches Compose to also serve `https://<your-mac-name>.local:8443`, and prints how to trust it on each phone or tablet (a one-time step per device). Plain `http://` keeps working.

## Back up the data

```sh
./scripts/backup.sh
```

This saves `backups/element-quest-<date>.sql.gz`. To run it every Sunday at 9 PM, add this line with `crontab -e` (use your own path):

```
0 21 * * 0 cd /Users/you/element-quest && ./scripts/backup.sh >/dev/null 2>&1
```

To restore one:

```sh
gunzip -c backups/<file>.sql.gz | docker compose exec -T db psql -U element element_quest
```

## Develop

Hot reload for both the UI and the API:

```sh
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

UI at <http://localhost:5173>, API docs at <http://localhost:5173/api/docs>.

Run the API tests locally (needs Python 3.13; uses SQLite unless `DATABASE_URL` points at Postgres):

```sh
cd api
pip install -r requirements-dev.txt
pytest
```

Change the database schema by editing `api/app/models.py`, then:

```sh
docker compose exec api alembic revision --autogenerate -m "describe the change"
```

Element facts live in `api/app/seed/data/*.json`, generated by `scripts/build_seed.py`. Seeding only adds missing rows, so edits made in the app are never overwritten.

## How learning works

Opening an element file adds its flashcards to the student's deck: its symbol, its family, and, where they apply, its valence electrons, an everyday use and its Latin name. Cards are scheduled with [FSRS](https://pypi.org/project/fsrs/): a wrong answer brings the card back within minutes, a right one pushes it days or weeks out, and a fast right answer (under 4 seconds) pushes it further. At most 20 brand-new cards are introduced per student per day. An element counts as **mastered** once all of its cards are scheduled at least 21 days apart. These limits are settings in `api/app/config.py` (`NEW_CARDS_PER_DAY`, `MASTERY_DAYS`, `EASY_ANSWER_MS`, overridable in `.env`).

## First session checklist

1. On the Mac: `docker compose ps` shows `db`, `api` and `web` running, with `api` healthy.
2. Sign in as **Parent / Teacher** and check **Manage → Accounts**: names, avatars, and a new password for each student if you don't want them to keep `elements`.
3. On each student's device, open `http://<your-mac-name>.local:<port>` and add it to the home screen.
4. Have each student sign in, tap **Surprise me** a few times, and open 5–10 elements. That fills their first deck.
5. Do one **Practice → Start review** together so they see how cards come back.
6. Over the next days, check the **Dashboard** for streaks, "Needs practice" and missed searches.
